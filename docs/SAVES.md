# Сохранение прогресса

В этой итерации пользователь выбрал **локальную проверку без облачной публикации**. В обычном Studio прогресс действует до завершения тестовой сессии: `StudioDataStoreEnabled=false`, `TestPlaceId=0`. Эти настройки оставлены выключенными.

## Что сохраняется

Схема `SchemaVersion=1`: монеты, XP, победы, открытые и выбранный след, день UTC, счётчики ежедневных заданий и полученные награды. Боевые состояния, персонаж, здоровье и текущий счёт забега не сохраняются. Старые записи версии 0 нормализуются; неизвестная новая версия блокирует запись старым сервером.

Облачный путь использует серверный `ProfileService`, `DataStoreService:GetDataStore()` и `UpdateAsync()` с ключами `Player_<UserId>`. Основное хранилище — `RuleRoomProfiles_v1`, изолированное тестовое — `RuleRoomProfiles_TEST_v1`. Клиент передаёт только действие и ID предмета/задания; цены, право получения награды и баланс проверяет сервер.

Загрузка атомарно получает блокировку с уникальным владельцем на 180 секунд. Автосохранение происходит примерно раз в 45–53 секунды; выход игрока и `BindToClose` сохраняют финальный снимок и освобождают блокировку. Записи одного игрока выполняются последовательно. Повтор запроса с потерянным ответом защищён `WriteToken`; метаданные записи сохраняются. Отрицательные ID локальных клиентов Studio не передаются как настоящие пользовательские ID.

Запросы учитывают бюджеты `StandardRead` и `StandardWrite`, делают до трёх попыток с задержкой и ограничивают окно повторов 15 секундами. Завершение сервера ожидает до 25 секунд. Уже выполняющийся запрос движка отменить нельзя: поздние ответы повторно проверяют владельца и при необходимости освобождают только свою блокировку. [Roblox: типы бюджетов](https://create.roblox.com/docs/reference/engine/enums/DataStoreRequestType).

После ошибки загрузки или конфликта сессий разрешена явно обозначенная игра без сохранения; её начальный профиль никогда не записывается поверх облачных данных. Если захват блокировки записался, но все ответы потерялись, отдельная ограниченная попытка освобождает только уникальную блокировку этой загрузки, сохраняя содержимое записи.

## Локальная проверка

Полная сборка включает обе группы проверок:

```powershell
powershell -ExecutionPolicy Bypass -File .\Build.ps1
```

Отдельный запуск из корня проекта:

```powershell
luau tests/ProfileData.spec.luau
lune run tests/ProfileService.integration.luau
```

Полученный результат: **59 проверок `ProfileData` и 27 интеграционных проверок в 9 сценариях прошли**. Интеграционный тест загружает настоящий исходник `ProfileService` без подмены его логики; локальные адаптеры заменяют Roblox-сервисы, часы, очередь задач и ответы сети.

Проверены покупка следа и получение награды задания с последующим сохранением/выходом/загрузкой новым экземпляром сервиса; повторное получение награды; режим Studio без доступа к хранилищу; ошибка загрузки без перезаписи данных; одновременные владельцы; потеря ответов после записи; медленное автосохранение одновременно с выходом и новой наградой; исчерпание бюджета при завершении; поздняя загрузка после ухода игрока. Это **локальная интеграционная проверка, не доказательство работы облака Roblox**.

## Что остаётся для облачной приёмки

Облачная проверка в этой итерации не выполнялась. Для неё позже понадобится отдельная опубликованная приватная тестовая experience/place, разрешённый доступ Studio к API, совпадающий `TestPlaceId` и явное включение `StudioDataStoreEnabled` только для этого теста. Studio обращается к настоящему облачному хранилищу; правила доступа описаны в [официальной инструкции Roblox](https://create.roblox.com/docs/tutorials/use-case-tutorials/data-storage/save-player-data).

Приёмка должна пройти через обычную игру: заработать монеты → открыть след → получить награду задания → выйти/остановить сервер → войти в новую серверную сессию → сверить баланс, след и флаг получения награды. Затем проверить быстрый повторный вход и два сервера с одним тестовым профилем. До этого сохраняется честный статус: локальная логика проверена, облачный цикл ещё не подтверждён.
