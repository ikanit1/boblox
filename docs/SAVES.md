# Сохранение прогресса

В этой итерации пользователь выбрал **локальную проверку без облачной публикации**. В обычном Studio прогресс действует до завершения тестовой сессии: `StudioDataStoreEnabled=false`, `TestPlaceId=0`. Эти настройки оставлены выключенными.

## Что сохраняется

Схема `SchemaVersion=1`: монеты, XP, победы, открытые и выбранный след, день UTC, счётчики ежедневных заданий и полученные награды. Боевые состояния, персонаж, здоровье и текущий счёт забега не сохраняются. Старые записи версии 0 нормализуются; неизвестная новая версия блокирует запись старым сервером.

Облачный путь использует серверный `ProfileService`, `DataStoreService:GetDataStore()` и `UpdateAsync()` с ключами `Player_<UserId>`. Основное хранилище — `RuleRoomProfiles_v1`, изолированное тестовое — `RuleRoomProfiles_TEST_v1`. Клиент передаёт только действие и ID предмета/задания; цены, право получения награды и баланс проверяет сервер.

Загрузка атомарно получает блокировку с уникальным владельцем на 180 секунд. Автосохранение происходит примерно раз в 45–53 секунды; выход игрока и `BindToClose` сохраняют финальный снимок и освобождают блокировку. Записи одного игрока выполняются последовательно. Повтор запроса с потерянным ответом защищён `WriteToken`; метаданные записи сохраняются. Отрицательные ID локальных клиентов Studio не передаются как настоящие пользовательские ID.

Запросы учитывают бюджеты `StandardRead` и `StandardWrite`, делают до трёх попыток с задержкой и ограничивают окно повторов 15 секундами. Завершение сервера ожидает до 25 секунд. Уже выполняющийся запрос движка отменить нельзя: поздние ответы повторно проверяют владельца и при необходимости освобождают только свою блокировку. [Roblox: типы бюджетов](https://create.roblox.com/docs/reference/engine/enums/DataStoreRequestType).

После ошибки загрузки или конфликта сессий разрешена явно обозначенная игра без сохранения; её начальный профиль никогда не записывается поверх облачных данных. Если захват блокировки записался, но все ответы потерялись, отдельная ограниченная попытка освобождает только уникальную блокировку этой загрузки, сохраняя содержимое записи.

## Выбор временной игры — 8 ноября 2026

Перед участием с временным профилем Welcome объясняет, что монеты, XP и покупки этой сессии не сохранятся. Основная кнопка явно называется «ИГРАТЬ ВРЕМЕННО», рядом остаётся «ОСМОТРЕТЬСЯ». Сообщение также доступно в лаборатории, коллекции и результатах. Обычная кнопка очереди или терминал не подтверждают этот выбор автоматически.

Сервер публикует `DataPersistent` вместе с прежним `DataStatus`:

| Состояние | Значение для игрока | Допуск |
|---|---|---|
| Loading / неизвестное состояние | Загрузка ещё не завершена | Пока закрыт, даже с переданным подтверждением |
| Saved + DataPersistent=true | Профиль загружен, сохранение включено | Обычный вход; это не обещание немедленной записи каждой новой награды |
| Unavailable + DataPersistent=true | Последняя запись не подтверждена, действующая аренда ещё позволяет автоматический повтор | Игра может продолжаться; показано предупреждение о задержке |
| Session / Busy / Unavailable + DataPersistent=false | Прогресс временный | Только после явного выбора временной игры |

`StationAction("Join", true)` передаёт намерение принять временный режим. Второй аргумент необязателен; если указан, он может быть только boolean. Строка, число или таблица не являются согласием. Сервер проверяет статус, живого персонажа, положение в лаборатории, отсутствие активного участия и частоту запросов. Принятый выбор записывается в серверный `TemporaryPlayAccepted`; `TemporaryPlayPrompt` управляет запросом существующего окна Welcome. Повторный вход в очередь в пределах того же принятого временного режима не требует повторять предупреждение. Explore закрывает окно, сохраняя отсутствие согласия.

При утрате аренды `DataPersistent` становится false, прежнее согласие сбрасывается. Уже начатое испытание не прерывается окном или телепортацией; заработанное в нём начисляется по прежним правилам. `ProfileService.IsReady` блокирует новый допуск, пока игрок не подтвердит временный режим. На безопасной границе после `InRound=false` Station выводит неподтвердившего игрока из очереди, очищает голос и возвращает в лабораторию к выбору. Это не включает запись временных наград в облако.

Purchase/Equip/ClaimQuest временного профиля до подтверждения отклоняются сервером; коллекция показывает причину. После восстановления обычного автосохранения старое сообщение об ошибке заменяется сообщением о восстановлении. Предупреждение об утрате сохранения не маскируется обещанием Saved.

Новой кнопки «перезагрузить профиль» внутри сессии нет: такая загрузка могла бы заменить заработанный временный прогресс. При действующей аренде работает существующий ограниченный автоматический повтор. Для постоянного fallback интерфейс предлагает закончить сессию и позже войти заново; временные награды при этом не переносятся. Схема профиля, настройки хранилищ и облачного доступа не изменены.

## Локальная проверка

Полная сборка включает проверки данных и поведения допуска:

```powershell
powershell -ExecutionPolicy Bypass -File .\Build.ps1
```

Отдельный запуск из корня проекта:

```powershell
luau tests/ProfileData.spec.luau
luau tests/ProfileStatus.spec.luau
lune run tests/ProfileService.integration.luau
lune run tests/StationAdmission.integration.luau
```

Ранее зафиксированный результат: **59 проверок `ProfileData` и 27 интеграционных проверок в 9 сценариях прошли**. Интеграционный тест загружает настоящий исходник `ProfileService` без подмены его логики; локальные адаптеры заменяют Roblox-сервисы, часы, очередь задач и ответы сети.

Проверены покупка следа и получение награды задания с последующим сохранением/выходом/загрузкой новым экземпляром сервиса; повторное получение награды; режим Studio без доступа к хранилищу; ошибка загрузки без перезаписи данных; одновременные владельцы; потеря ответов после записи; медленное автосохранение одновременно с выходом и новой наградой; исчерпание бюджета при завершении; поздняя загрузка после ухода игрока. Это **локальная интеграционная проверка, не доказательство работы облака Roblox**.

Дополнение 2026-11-08: **ProfileStatus — 30 проверок; ProfileService — 43 проверки в 12 сценариях; StationAdmission — 19 проверок, всё прошло**. Добавлены временное участие/покупка только после выбора, различие ошибки автосохранения и утраты аренды, восстановление сообщения, сброс устаревшего согласия, сохранение награды текущего этапа и повторный допуск после нового выбора. StationAdmission загружает настоящий `Station.server` и вызывает зарегистрированные обработчики RemoteEvent/ProximityPrompt/Heartbeat с локальными адаптерами. Проверены неверные типы согласия, границы/частота запросов, отсутствие прерывания активного этапа, безопасный возврат к выбору и отключение обработчиков при cleanup. Успешные локальные адаптеры не заменяют native-клиентов Studio, настоящий телефон или облачный цикл; эти проверки в данном проходе не выполнялись.

## Что остаётся для облачной приёмки

Облачная проверка в этой итерации не выполнялась. Для неё позже понадобится отдельная опубликованная приватная тестовая experience/place, разрешённый доступ Studio к API, совпадающий `TestPlaceId` и явное включение `StudioDataStoreEnabled` только для этого теста. Studio обращается к настоящему облачному хранилищу; правила доступа описаны в [официальной инструкции Roblox](https://create.roblox.com/docs/tutorials/use-case-tutorials/data-storage/save-player-data).

Приёмка должна пройти через обычную игру: заработать монеты → открыть след → получить награду задания → выйти/остановить сервер → войти в новую серверную сессию → сверить баланс, след и флаг получения награды. Затем проверить быстрый повторный вход и два сервера с одним тестовым профилем. До этого сохраняется честный статус: локальная логика проверена, облачный цикл ещё не подтверждён.
