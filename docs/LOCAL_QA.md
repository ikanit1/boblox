# Проверка локального кандидата RuleRoom

Инструменты подготавливают воспроизводимую приёмку. Они не превращают адаптеры в Roblox-клиентов и не подтверждают облако, звучание, удобство пальцами или удержание.

## Сборка и идентичность

Из корня проекта выполнить `powershell -ExecutionPolicy Bypass -File .\Build.ps1`. Сборка сначала фиксирует написанные исходники/инструменты/конфигурацию, затем генерирует ассеты и проверяет неизменность этих входов. Полный снимок, включая новые ассеты, снимается **до** проверки геометрии и статических проверок. После Rojo и тестов подтверждаются неизменность снимка и совпадение каждого Source внутри места с исходником. Поддержаны оба XML-представления Source: string и ProtectedString.

Результаты в игнорируемой Git папке `build/`:

- `RuleRoom.rbxlx` — основное локальное место с десятью правилами.
- `RuleRoomExperiments.rbxlx` — отдельные Studio-only прототипы; не замена основному месту и не релизные правила. Их отдельный Source/хеш также проверяется манифестом. Инструкция — [прототипы](../prototypes/README.md).
- `candidate-generation.json` — снимок написанных входов до генератора.
- `candidate-inputs.json` — полный снимок входов до всех проверок и Rojo build.
- `candidate-manifest.json` — SHA256 входов/места, base commit, dirty flag, версии из закреплённого toolchain, список совпавших скриптов.

Перед использованием старого артефакта: `python tools/candidate_manifest.py verify`. Изменение исходника, теста, генератора, ассета или самого места отклоняет прежнее соответствие. Новый/удалённый незакоммиченный файл тоже учитывается. При dirty tree `candidateCommit = null`; base commit нельзя выдавать за проверенный SHA кандидата. Манифест не утверждает запуск CI/Studio и не создаёт release tag.

В CI манифест входит в артефакт вместе с местом. Workflow должен реально выполниться для выбранного коммита; изменение YAML локально не является успешным GitHub Actions.

## Ограниченный сборщик производительности

`tools/studio/performance_probe.luau` — временный диагностический исходник. Он **не включён** в Rojo mapping и отказывается работать вне Studio. После подключения редактора его можно установить как Script на сервере или LocalScript клиента внутри Play-сессии. Он не двигает персонажа, не читает PlayerModule и не отправляет сетевые события.

До запуска задать атрибуты скрипта:

- `SourceFingerprint` — 64-значный fingerprint текущего `candidate-manifest.json`.
- `DurationSeconds` — 15–1800 секунд; по умолчанию 120.

Переданный fingerprint — метка оператора, **не автоматическая аттестация загруженного Studio**. Перед приёмкой отдельно сопоставить реальные Source редактора и собранное место. JSON содержит `SourceIdentityCheck = caller_supplied_not_attested`.

На сервере результат находится в `ServerStorage.RuleRoomPerformance`, у клиента — в `PlayerGui.RuleRoomPerformance`. `Complete=true` означает только окончание записи; `SummaryJSON` содержит агрегаты. Для досрочной остановки поставить папке `Stop=true`. Удаление папки/скрипта отключает наблюдение. Перед повтором экспортировать и удалить только эту диагностическую папку/скрипт.

Сборщик сохраняет:

- интервалы RenderStepped клиента или Heartbeat сервера в миллисекундах;
- p50/p95/p99 **последних максимум 6000 интервалов**, nearest-rank; lifetime mean/min/max отдельно;
- до 1800 отсчётов общей памяти и сырых `Stats.DataSendKbps`/`DataReceiveKbps` с частотой не выше 1 Гц;
- последние 60 снимков фазы, номера забега/этапа, числа игроков, Instances, памяти и временных эффектов; вытесненные записи подсчитываются;
- перечень недоступных метрик вместо выдуманного нулевого потребления.

JSON ограничен 32000 байт: превышение выдаёт `ExportSizeLimit`, а не обрезанный успешный отчёт. Frame delta не равен CPU/GPU-времени; Heartbeat не равен задержке обработчика опасности; сетевые скорости не являются RTT. Сведения Stats предоставляет движок, общий счётчик Instances включает объекты за пределами проекта. [Официальный API Stats](https://create.roblox.com/docs/reference/engine/classes/Stats).

Локальные тесты проверяют арифметику, кольцевые буферы, длинную синтетическую запись, размер экспорта и cleanup. Реальные p95, нагрев и утечки фиксируются только на выбранном устройстве и в сопоставимых фазах прогретой игры.

## Следующий настоящий прогон

После подключения Studio начать с двух клиентов и текущего fingerprint: полные забеги, 0/6, обычный финал/Forfeited, новая попытка, вход/выход/Reset по фазам. Затем увеличивать состав в поддерживаемом окружении. Число адаптеров Lune не заменяет число клиентов.

На телефоне: Rule/Warning/Forfeited/Results, примерка и достижения, штатные multi-touch и безопасные зоны экрана. Проверить mute, сокращённые эффекты и звук на слух. Облачный цикл требует отдельно разрешённой приватной тестовой публикации; здесь он не выполняется.

Внешние наблюдения: [сценарий и бланк плейтеста](playtest/PROTOCOL.md). Критерии остаются в [канонической дорожной карте](obsidian-vault/07-Tasks/Roadmap.md).

## Интегрированный кандидат: 12 правил

Актуальный отчёт — [PRODUCT_COMPLETION](PRODUCT_COMPLETION.md). Новые правила исполняются основным местом; prototypes оставлены как отдельная исследовательская история. Studio fixtures дополнены зелёными целями новых правил и концом реальной стадии стабилизации; в этом проходе они только проверяются локально, не запускаются в Studio.

Экспорт performance_probe теперь содержит RuleId и ActivePlayers. Скопировать [performance-context.example.json](release/performance-context.example.json), заполнить только фактически наблюдённые устройство/качество/сеть/состав/сценарий, затем:

```powershell
python tools/candidate_manifest.py verify
python tools/validate_performance.py --capture evidence/capture.json --context evidence/context.json --output evidence/review.json
```

Сценарии: full_arena, meteors, reactor, respawn_results, collection, repeated_runs, phone_soak. Обычная запись требует минимум 120 секунд; phone_soak — 1800 секунд и физическое устройство, repeated_runs — минимум 10 завершённых забегов. Это внутренние требования сбора, не измеренные показатели нынешнего кандидата. Client p95 сравнивается с бюджетом 30/60 FPS; Heartbeat не трактуется как время игрового обработчика. Нет общего произвольного лимита памяти вместо устройства.

Статусы Missing/Incomplete/Invalid/NeedsInvestigation не проходят. Даже ReadyForReview означает только готовность выгрузки к рассмотрению; nativeAcceptance всегда false. Сопоставление Source редактора и артефакта подтверждает оператор отдельно. Пустые, нечисловые или несогласованные метрики, неправильное правило и игроки только в лобби не считаются достаточной записью. Отсутствующие реальные данные сейчас не заменены синтетическим отчётом.

После полного Build и актуализации журнала `python tools/package_candidate.py` собирает build/RuleRoom-LocalCandidate.zip. Упаковка сверяет манифест, файл игры и машинный отчёт перед записью, затем контрольные суммы каждого файла внутри ZIP. Выход допускается только как .zip в build, чтобы не затереть исходник. Это локальная передача без публикации.
