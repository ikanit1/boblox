# Проверка столкновений персонажей

Дата: 23 октября 2026. Studio **0.744.0.7441077**. Отдельная ветка `fix/character-collisions` основана на main; исправления исходов финала из отдельной ветки стабилизации в её базу не входят. Этот отчёт охватывает столкновения персонажей и не переносит приёмку ReactorRush из другого PR.

**Статус:** дефект воспроизведён двумя клиентами; диагностический A/B, новый Play на точном production-коде исправления и 22 проверки жизненного цикла прошли. Дополнительно проверен отдельный объединённый preview; исходные настройки Studio восстановлены.

Итоговые сборки Collisions и объединённого Candidate прошли.

## Воспроизведение

В основном цикле с двумя клиентами игроки на LowGravity при обычных командах MoveTo/Jump поднимались выше Y=110 и погибали. Затем изолированный сценарий с production-правилами/roster, выключенным Main и mock-профилями воспроизвёл это поведение. В Spinner один из игроков выбывал с MovementViolation=Airborne.

Автоматический драйвер временно отключал только стандартные Controls через `PlayerModule:GetControls():Disable()`; камера продолжала работать. Упреждение прыжка — 5 studs. Это физическое движение через Humanoid, не телепортация и не подстановка здоровья. Проверка не является человеческим плейтестом или испытанием облачных сохранений.

## Диагностический повтор A/B в Studio

После исходных четырёх сценариев оба персонажа переведены в временную collision group `QA_NoPlayerCollision`, для которой взаимная коллизия выключена. Повторены те же четыре сценария с тем же обычным драйвером. Намеренно изменялось только столкновение игроков между собой; параметры движения, гравитации и урона не менялись.

| Сценарий | До отключения взаимных коллизий | После отключения |
|---|---|---|
| LowGravity / solve | Player1: maxY 110.05, HP 0; Player2: maxY 110.37, HP 0; survival-наград нет | Оба HP 100, maxY около 29.675, по 7 попыток прыжка; звёзды 3/6, по одному survival/completion |
| Spinner / solve | Player1: HP 0, Airborne, maxY 15.27, survival 0; Player2: HP 72.05, survival 1 | Player1: HP 100, Player2: HP 76.10; maxY около 11.26/11.27, Airborne нет, survival/completion по одному |
| LavaRise / solve | Оба HP 100, по одному survival/completion | Оба HP 100, по одному survival/completion |
| LowGravity / no_pickups | Оба HP 100, попыток прыжка 0, звёзд 0, survival/completion по одному | Тот же ожидаемый исход: отсутствие прыжков не даёт звёзды и не требует смерти |
| Очистка | У всех четырёх записей productionRestored=true до резервной очистки | У всех четырёх записей productionRestored=true; recovery.attempted=false |

LowGravity / no_pickups в JSON записан как behavior=mistake с уточнённой отрицательной целью. Отрицательный сценарий бонусного правила проверяет отсутствие собранных звёзд.

Локальные записи находятся в соседнем checkout `RuleRoomStability/build`: `contact-rules-complete.json` / `.parsed.json`, `contact-ab-change.json`, `contact-ab-collision-off.json` / `.parsed.json`. Запись изменения подтверждает collidable=false и двух игроков. Диагностическое сравнение поддерживает вывод о влиянии взаимных контактов на воспроизведённый вылет; это один локальный повтор, не гарантия отсутствия всех физических проблем или полного античита.

## Повтор на production-коде кандидата

В новом Play загружены точные исходники checkout RuleRoomCollisions, без временного `QA_NoPlayerCollision` из диагностики. `build/candidate-groups.json` подтвердил у обоих персонажей группу `RuleRoomCharacters`: self=false, world=true, groupExists=true. Взаимные коллизии выключены, столкновения с миром сохранены.

| Сценарий | Фактический результат |
|---|---|
| LowGravity / solve | Player1: HP 100, maxY 29.671, 5 звёзд; Player2: HP 100, maxY 29.675, 4 звезды. MovementViolation не зарегистрирован |
| LavaRise / solve | Оба HP 100, maxY около 11.16, по одному survival/completion |
| Spinner / solve | Player1 HP 100, Player2 HP 76.12; maxY около 11.25/11.27, Airborne нет, по одному survival/completion |
| LowGravity / no_pickups | Оба HP 100, попыток прыжка 0, звёзд 0, по одному survival/completion; отрицательная цель достигнута |
| Очистка | Во всех четырёх записях productionRestored=true, recovery.attempted=false |

Источник: `build/candidate-rules-complete.json` / `.parsed.json`. Это изолированные production-правила/roster с mock-профилями, а не повтор полного забега с реальной экономикой. Параметры движения и урона сохранены; упреждение тестового прыжка осталось 5 studs.

## Жизненный цикл: 22 проверки в Studio

Это изолированный production roster с mock-профилями вне активного испытания; он проверяет управление collision groups и подписками, а не игровой успех или награждение.

## Дополнительный объединённый preview и завершение QA

Отдельный `RuleRoomCandidate` собран из PR1 + PR2 + PR3 без merge. Он включает исправления исходов финала из другой ветки; этот результат **не приписывает их standalone-ветке коллизий на base main**. Два полных production-забега с двумя клиентами завершены: 24 проверки наград «испытание × игрок», четыре суммы забегов, восстановление комнаты и ResultsStable прошли; MovementViolation пуст в обоих забегах.

В первом забеге оба пережили шесть испытаний, заряд 11/5 и finale=true, каждому +1 Wins; с нулевого профиля получено 125/141 Coins и 172/196 XP. Во втором оба пережили пять испытаний, затем естественно погибли после зарядки 6/5: HP 0, finale=false, Wins не изменились. Суммы второго забега +81/+99 Coins и +134/+161 XP; искусственных инъекций здоровья/позиции не было. Источник: `RuleRoomCandidate/build/combined-production-complete.json`, Status=PASS, SummaryPassed=true, 31 запись, 277.78 s.

После QA обе Studio-сессии оставлены в Edit с Main.Enabled=true, QA=[], device=default, PlaceId=GameId=0. Исходные 500/500 ms задержки и 0.5/0.5% потерь восстановлены и прочитаны обратно; оба клиентских Controls включены перед EndTest. Локальные подтверждения: `RuleRoomStability/build/final-cleanup-3eae58be.json`, `final-cleanup-bb5ceda0.json`, `final-source-restored.json`, `RuleRoomCandidate/build/controls*.json`. Возврат настроек не является повтором тестов под задержкой.

Не заявляются приёмка 12 игроков, физического телефона/геймпада, сетевой матрицы задержек/потерь, облачных профилей или всей игры. Исходные настройки Studio имели добавленную задержку 500 ms в каждую сторону и 0.5% потерь; описанные A/B-прогоны выполнялись без добавленной задержки.
