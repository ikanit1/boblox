# RuleRoom alpha contract — 2026-10-23

Canonical repository: https://github.com/ikanit1/boblox, branch main. This supersedes CONTRACT.md (historical prototype). Rojo files are authoritative. User explicitly expanded the prototype into a full playable mode; GitHub pushes are authorized. Cloud game publication and paid products are separate.

## Gameplay
One laboratory complex, 1–12 intended players, six trials per run. First entry waits for an acknowledged Play/Explore choice. Voting 8s -> five distinct drawn trials -> ReactorRush cooperative finale -> Results 12 s. Trials last roughly 12–31s including warnings; breaks 3s. Living survivors remain on the restored arena during breaks; results return the queue to the laboratory. Death eliminates for this trial only; next trial restores health and admits respawned players and late joins. Never spawn mid-hazard. No paid revival. Solo works; runs last about 2–4 minutes.

Rule catalog: SafeColor, LaserSweep, LowGravity (existing), RedLight (stop on red, grace before movement checks), LavaRise (safe platforms), MeteorRain (marked impacts), DisappearingTiles (warned waves), SafeZone (marked safe zone), Spinner (jump a rotating beam), PressureWave (change shelter behind energy screens), ChangingWalls (align with a moving full-height opening), ReactorRush (collect energy together, then survive four seconds of stabilization). Every hazard warns, validates on server, and cleans up unconditionally.

Modes Balanced / Reflex / Cosmic alter deck weights, not movement stats or rewards. No repeats within a run; readable first trial, finale last. Pure seeded deck module. No rewards for lobby idling.

## World
Preserve Workspace.Arena, Tiles (36 anchored 14x2x14 Parts at x/z -35,-21,-7,7,21,35, y=0), ColorName Blue/Pink/Yellow/Green; ArenaSpawn (0,5,0), LobbySpawn (0,4,158), hidden noncollidable Laser. The arena spans 84x84. Lobby platform spans 180x144, X -90..90 / Z 48..192; a narrow viewing bridge stops at the arena boundary. Dynamic hazards under RuleEffects, destroyed on reset. No permanent collision inside the trial grid; no supporting slab or jump obstruction. World safety tests enforce this boundary. Native original scenery, no uploaded meshes or paid assets.

Optional station: seven ordered parkour checkpoints, ten rule-guide terminals, wardrobe terminal, viewing gallery and live server score board. Explore keeps the player out of admissions and voting until Join. New players start with LobbyOnly=true and EntryChoiceMade=false; accepted Join/Explore/Practice sets the choice flag. Main guards that flag even before Station has initialized. StartPractice is a proximity-only server action, permitted outside a trial; new/exploring players use the full Course in Explore, while confirmed queued players keep Queue for the two-checkpoint Warmup. Falling restores the last checkpoint. A valid ordered finish updates PracticeBestSeconds and submits the server-measured time to ProfileService.RecordPractice; persistence follows the profile's current data status. No currency, XP or run-win reward for practice/exploration. Join cancels practice and admits only at a normal trial boundary. Lunar gravity is applied only to admitted trial characters with temporary mass-scaled VectorForces; global scene gravity stays 196.2. A server-owned root TrialGravityScale selects the matching airborne envelope. Restore destroys every force/attachment and clears that attribute. Source: tools/build_station.py and Station.server/client scripts.

## Protocol
ReplicatedStorage.RuleRoomState attributes:
- Phase: Waiting / Voting / Rule / Break / Results.
- RuleId, RuleName, Instruction, PhaseEndsAt, Round, RuleIndex, RuleCount (6), SafeColor, Accent: existing meanings.
- ModeId: Balanced / Reflex / Cosmic; VotesBalanced, VotesReflex, VotesCosmic integers.
- TeamCharge, TeamGoal numbers; FinaleSuccess boolean; ResultsText string; AliveCount number.
- HazardStage: Warning / Active / Recovery; HazardCycle increments for each warning wave within a trial. These are presentation signals, not client permissions.

ReplicatedStorage.RuleRoomRemotes contains authored Vote, ProfileAction and StationAction RemoteEvents. Vote: FireServer(modeId), server allowlist, Voting phase only, replace previous vote, remove on leave/Explore, rate limit. ProfileAction: FireServer(action, id), action Purchase/Equip/ClaimQuest/EquipTitle plus SetPreference(key, value); server allowlisted id, price, ownership, eligibility and balance, rate limit; temporary profiles require the explicit entry choice below before these actions. StationAction: FireServer("Explore" | "Join", acceptTemporary?), living character within the station, outside active participation, 0.4s server rate limit. The optional second argument is a boolean only. StartPractice uses the authored ProximityPrompt only, checks exact ownership in the lobby, <=13 studs, living character, phase membership and rate. Guide/wardrobe prompts display local information; purchases still use ProfileAction. Never client-supplied money/scores/positions/prices/checkpoint/time.

Station player attributes: LobbyOnly and EntryChoiceMade booleans; PracticeState Idle/Running/Finished; PracticeCheckpoint 0..7; PracticeStartedAt server time or 0; PracticeLastSeconds is a session-only positive time, while PracticeBestSeconds is the compatibility display seeded from the profile's BestPracticeSeconds (see Progression API). Main ignores explorers and unconfirmed newcomers in queued counts, voting and trial admission. EndRound does not teleport an explorer. The schema-v5 records, mastery, preferences and rollback boundary are defined below.

Runtime save/entry update — 2026-11-08:
- DataPersistent boolean is published by ProfileService before DataStatus. It is false while loading and for Session/Busy/permanent fallback, true while an acquired persistent profile remains writable. Unavailable + true means an automatic save retry is pending; Unavailable + false means memory-only progress. Saved does not claim that every later gameplay change has already been written.
- TemporaryPlayAccepted boolean is server-owned. It starts false and is reset when DataPersistent changes, including lease loss. In temporary mode only StationAction("Join", true) records the new choice; an already accepted temporary session may subsequently use Join without the argument. Loading, unknown DataStatus, and Saved without DataPersistent=true cannot be bypassed with true. Malformed arguments, active-trial requests, out-of-bounds requests and cooldown violations remain rejected.
- TemporaryPlayPrompt boolean is server-owned and initialized false. Join without consent, including the world prompt, requests the existing Welcome choice instead of admission. Accepted Join/Explore/Practice clears this prompt. Explore does not grant consent.
- Lease loss never opens the modal or teleports a player during InRound. Current-trial awards remain eligible under the existing reward checks. When InRound becomes false, Station removes the unconsented temporary player from the queue, clears their vote, returns the character to the lobby if needed and opens the choice. New trial admission/eligibility requires the explicit choice; accepted temporary progress never enables cloud writes.
- No reload/reacquire action was added inside the session: replacing a fallback profile could discard earned temporary progress. Existing live-lease automatic saves continue their bounded retry; permanent fallback explains that a later rejoin starts a new loading attempt and does not transfer temporary rewards.

Player attributes: InRound, Eliminated, RunScore, RunSurvived, Coins, XP, Level, Wins, EquippedTrail, Owned_<id> booleans, DataStatus (Session/Loading/Saved/Unavailable/Busy), Quest_survive/stars/runs counts, Claimed_survive/stars/runs booleans, ActionMessage. leaderstats Score and Best remain session scores. RunScore and RunSurvived reset only at BeginRun, not per-trial StartRound.

Personal run display: TrialOutcome_1..6 (Pending/Playing/Survived/Forfeited/Eliminated/Skipped), TrialRule_1..6 rule IDs, LastTrialOutcome/LastTrialRule, RunStars, RunCoinsEarned/RunXPEarned. Forfeited means the participant is still alive at the trial boundary but movement validation forfeited their trial reward; it counts as participation for first-entry/late-entry presentation, neither a rewarded survival nor an elimination. LastTrialOutcome publishes the same value. A second movement violation still publishes Eliminated. Reward totals capture synchronous attribute changes only around ProfileService's real grants; purchases and quest claims never enter these totals. RunResult is None/Won/FinaleFailed/FinaleMissed/NotEnoughTrials/NoSurvival/Aborted; ResultReady is published last. BeginRun resets the display, respawn does not. LastDamageRule/LastDamageAt are server-authored; EliminationReason distinguishes hazard, fall, boundary, movement and reset. These values do not change save schema or reward eligibility.

ReactorRush team success requires a completed finale, its existing team charge goal and at least one living survivor, including Forfeited participants. A living Forfeited finalist does not gain a personal finale success or win; ordinary personal win eligibility still requires four rewarded trial survivals and a non-forfeited finale survival.

Roster APIs: BeginRun(deck?), StartRound(cframe,index?,ruleId?), EndRound(keepInArena?), CompleteRun(teamSuccess,aborted?). The optional legacy arguments support isolated fixtures; production Main supplies the deck and index. CompleteRun is guarded for all records, including zero-survival and aborted outcomes; aborted runs never receive a completion bonus.

AwardSurvivors(ruleId) -> (awarded, forfeitedAlive): the first result remains the count of newly rewarded survivors; the second is the current count of living admitted forfeited participants above the survival floor (root Y >= 1). Forfeited publishes the trial outcome without awarding points, survival rewards, mastery, record.survived or record.finale. Repeated calls grant nothing twice and report the still-living forfeited count again; eliminated, departed or replaced characters do not count. EndRound preserves Forfeited and also publishes it for a still-valid warned survivor when no award pass ran. ForfeitedAliveCount() -> number is a read-only query for the same finalized living group; it becomes zero after EndRound. Main captures both AwardSurvivors results only when the trial completed and uses awarded + forfeitedAlive > 0 for FinaleSuccess, without invoking awards a second time.

RunResult keeps its existing values: a forfeited finale has no personal finale-survival credit and can produce FinaleMissed or NoSurvival, never Won. Presentation must consult TrialOutcome_6/LastTrialOutcome to explain "alive, reward forfeited" rather than infer death from the absence of a personal win. Ordinary completion rewards earned from earlier eligible trials are unchanged.

## Progression API
Main creates ProfileService.new() once, then PlayerRoster.new(lobbyCFrame, profiles). Dot-methods:
- IsReady(player) -> boolean. The scope must be loaded/current, and temporary profiles must have TemporaryPlayAccepted=true. Persistent profiles with a live lease may continue while an automatic save retry is pending. This method gates new admissions/voting, not awards already earned by an admitted player. Failed loading may play after the explicit session-only choice, but never save fallback over a failed record.
- AwardSurvival(player): +12 coins/+20 XP, daily survive count; once per completed trial/eligible player. PlayerRoster never invokes this grant for a movement-forfeited trial, which also does not increment RunSurvived or personal finale eligibility.
- AwardStar(player) -> boolean accepted: +2 coins/+3 XP, daily stars count. Roster updates score, RunStars, RunEnergy and trial pickup proof only after acceptance; rejected grants cannot qualify mastery.
- CompleteRun(player, won): +15 coins/+25 XP, daily runs; +1 Wins/+20 coins if won. Main calls exactly once per run for participants who survived at least one trial. won = survived >=4 trials AND survived finale AND team goal completed. On the first accepted completion, updates BestRunScore / BestRunSurvived from the server-owned RunScore / RunSurvived attributes and publishes NewRecord as "", "Score", "Survived" or "Score,Survived". Equal/lower values do not set a record; duplicate completion changes neither records, notice nor rewards. PlayerRoster resets NewRecord to "" in resetRunDisplay at a new run.
- RecordPractice(player, seconds) -> boolean bestImproved. Uses readyScope; accepts only a finite number with 0 < seconds <= 1,000,000,000. A first or strictly faster time updates BestPracticeSeconds, preserving fractional seconds. Any valid full-course finish can unlock the Practice title, including a slower first finish after migration; the return value still describes the best time only. It grants no coins, XP or wins. Station validates all seven checkpoints and computes time on the server before invoking this method once. Two-checkpoint warmup never calls it.
- RecordFlawless(player, ruleId, action?) -> boolean changed. Uses readyScope; requires a string in GameConfig.RuleOrder, InRound=true and no MovementWarning. Increments Flawless[ruleId] at most once per server Round/RuleIndex and grants no currency. Optional action is the server-only literal "Collected": Roster supplies it only after an accepted pickup in this trial. The legacy two-argument call grants no Collector milestone progress. PlayerRoster calls it only for an eligible current-trial survivor: no recorded damage, no movement reward forfeiture and matching ruleId. HealthChanged is tracked for the full trial and supplemented by the synchronous LastDamageAt/LastDamageRule journal; healing cannot erase damage. New hazard code must journal damage before applying it, as ArenaRules does. Damage subscriptions are cleaned up when participation ends.
- Destroy(): bounded flush/release, no overlapping saves.

Persistent record attributes on Player: BestRunScore (integer 0..1,000,000,000), BestRunSurvived (integer 0..GameConfig.RuleCount, currently 6), BestPracticeSeconds (positive finite seconds or absent/nil when no record), and Flawless_<RuleId> (integer 0..1,000,000,000 for every GameConfig.RuleOrder entry; missing stored counts replicate as 0). NewRecord is a session-only notification, not a saved profile field. PracticeBestSeconds remains the compatibility display attribute: Station seeds it from BestPracticeSeconds, handles asynchronous profile loading and keeps the faster of the saved and current-session times. PracticeLastSeconds remains session-only. This record contract supersedes the earlier session-only description of the parkour best above.

Server bridge: ProfileService.new creates ServerScriptService.RuleRoomServer.RuleRoomRecordPractice, a BindableFunction whose OnInvoke calls the existing service's RecordPractice. The callback is assigned before parenting; Destroy removes the endpoint. Station discovers it lazily and removes the finished attempt before Invoke, since Invoke may yield. No global service registry, second profile service, client RemoteEvent or generated-model change is needed. A missing/failing endpoint leaves the local result available with a bounded server warning; it does not claim persistence.

EconomyConfig.Trails array {Id, Name, Price, Color}, default None free and four earnable trails, first ~60 coins. EconomyConfig.Quests keyed survive/stars/runs with Name, Target 8/10/2, Reward 50/50/60. Start Coins=0, XP=0. Level from XP, cosmetic only. Define exact catalog IDs before presentation uses them.

ProfileService owns Player events and ProfileAction. Persistence: server only, schema validation/migration, UpdateAsync, session lease, budget/backoff, autosave, PlayerRemoving/BindToClose. Studio in-memory by default; explicit development config and published sandbox needed for real persistence. Never overwrite after load failure/lock conflict. Separate production/test store names. No Robux products in this alpha.

Record persistence uses SchemaVersion=5 in the existing RuleRoomProfiles_v1 / RuleRoomProfiles_TEST_v1 stores; the suffix is not the schema version. Versions 0/missing, 1, 2, 3 and 4 normalize into v5 without dropping valid legacy balances, XP, wins, ownership/equipment, current-day quests/claims or v2 records/Flawless. The v3 fields Mastery (milestone ID to bounded progress), CleanCollectors (three allowlisted rule booleans), UnlockedTitles and EquippedTitle ("None" by default) remain intact for v3 migration. Preferences introduced in v4 remain intact. V5 protects the expanded rule/cosmetic allowlists from older writers. Old wins/Flawless do not prove an active pickup, so new goals start empty only when migrating versions before v3. Each counter is capped at its catalog Target; Collector is derived from CleanCollectors. UnlockedTitles is reconstructed only from completed server progress, and equipped IDs must be unlocked. clone deep-copies all maps. The existing autosave, lease and final-save path persists these fields; no cloud request per pickup/title.

Rollback boundary: a server whose supported ceiling is v1/v2/v3/v4 cannot acquire v5 data (FutureSchema, or Busy first while another owner's lease is active); the existing raw.SchemaVersion guard refuses a mismatched save as SchemaChanged. Cleanup may release only its own lease while preserving v5 contents. Never lower SchemaVersion or change store names to bypass this protection. A saving rollback requires a compatible reader/writer; otherwise affected users receive the explicit temporary-profile fallback without overwriting v5. Local tests use a service adapter with the old schema ceiling, not a historical binary or real cloud.

Permanent goals: EconomyConfig.MasteryMilestones entries are {Id, Title, Description, Goal, Target}. FirstRun (1): an eligible completed run with RunStars>0. PerfectRun (1): personal win with all six survivals and RunEnergy>0. Collector (3): distinct damage-free, warning-free LowGravity/RedLight/ReactorRush survivals with an accepted pickup in that trial. Practice (1): valid full-course finish. TeamVeteran (5): five personal wins with RunEnergy>0. Automatic, one-time rewards are cosmetic titles only; no currency or movement changes. Skipped, reset, forfeited and aborted completions cannot manufacture these actions.

Player attributes: Mastery_FirstRun/PerfectRun/Collector/Practice/TeamVeteran (integer 0..Target), UnlockedTitle_<same ID> (boolean), EquippedTitle ("None" or an unlocked milestone ID). ProfileAction("EquipTitle", id) uses the same readiness/cooldown gates as purchases and accepts only None or an unlocked catalog ID. Client UI never unlocks a title. Session profiles keep these goals temporarily and say so.

## Roadmap iteration protocol — 2026-11-08

LowGravity has nine shared pickup positions but a personal quota of three accepted stars per admitted character. Player LunarStarMask (0..511), LunarStarCount (0..3), LunarStarGoal (3 during admission, 0 after cleanup); each point has LunarStarIndex (1..9). A character/admission snapshot prevents respawn, late entry or departure from gaining/inheriting a quota. Server validates distance and accepted award before setting the mask. Other players do not consume your stars. Client visibility is cosmetic only; there is no collection remote.

Queue warmup reuses the existing practice prompt and two checkpoints without leaving Queue or resetting a vote. Full Course still requires Explore and seven checkpoints. PracticeMode is ""/Warmup/Course, PracticeGoal is 0/2/7, PracticeState remains Idle/Running/Finished. Missing attributes before the first attempt are allowed. InRound=true cancels warmup immediately without teleporting over Main's admission. Warmup grants no money, XP, last/best time or RecordPractice call.

ServerStorage.RuleRoomControls is a server-only Folder with boolean Disabled_<RuleId> flags, default false. Ordinary rules can be excluded from the next deck. ReactorRush is mandatory: disabling it, invalid known flags, insufficient ordinary rules or no legal/readable sequence pauses new runs. RuleRoomState.RunsPaused=true and RunPauseReason explain this Waiting state; no Round increment, admission or awards occur. Main checks before Voting and again before BeginRun; an active deck is immutable. Restoring a legal configuration resumes Voting. Flags are local to this server, not global/persistent rollout settings; no management remote exists.

Social results: RuleRoomState.ContributionsJson is one bounded JSON snapshot (<=32000 bytes), ContributionsRound is its publication barrier. Payload {Version=1, Round, Players=[{UserId,Name,Score,Survived,Energy,Outcome,Left}], Truncated}. At most 72 admitted identities (12 players × 6 trials); missing/late spectators are excluded. Rejoined identities combine their actual segment contribution, while Outcome remains the current personal result; departed participants use Left. Snapshot does not grant rewards. Client requires payload.Round == ContributionsRound == state.Round and shows an optional 12-row page inside Results. Invalid/stale data hides the optional list. Truncation is explicit.

Analytics uses RuleRoomSessionV2: Joined → FirstTrialStarted → FirstResultsAvailable (including 0/6 and aborted) → RepeatIntent → IntentionalNextRunStarted. ResultsAvailable is server availability, not proof of UI viewing. Intent means an accepted Join or Vote after results; automatic admission is not intent, and later intent does not relabel an already-started run. Custom events RRV2_RunStarted, RRV2_ResultsAvailable, RRV2_RepeatIntent and RRV2_ProfileState use fixed labels. Queue depth <=32/player, funnel retry <=3 with the same identity; ambiguous custom failures are not retried. Player diagnostics AnalyticsVersion=2, AnalyticsStep, AnalyticsEvents, AnalyticsLastEvent, AnalyticsDeliveryEnabled, AnalyticsQueueDepth, AnalyticsDropped, AnalyticsDeliveryFailures, AnalyticsJoinIntent. Studio delivery remains off.

## Audio and preferences — next roadmap package, 2026-11-08

Profile schema v5 stores Preferences with only explicit choices: EffectsVolume, MusicVolume (finite number 0..1), AudioMuted and ReducedMotion (boolean). Absent values remain absent, distinct from explicit false/zero. Defaults in PlayerPreferences are 1, 0.5, false, false. Finite out-of-range stored volumes are clamped; requests are rejected instead. Existing v3 Mastery/CleanCollectors/UnlockedTitles/EquippedTitle and all earlier progress migrate intact. Older writers cannot silently discard Preferences or newly cataloged progress: FutureSchema/SchemaChanged applies to v5, including release-only cleanup of their own lease.

Server Player attributes PrefEffectsVolume, PrefMusicVolume, PrefAudioMuted, PrefReducedMotion are absent when unset; PrefsReady=false while loading, true after server publication; PrefsRevision starts at 0 for this service session. ProfileAction("SetPreference", key, value) uses the normal loaded/current scope, temporary-consent and rate gates. Only the four keys and proper value types are allowed. Accepted requests increment PrefsRevision even for an unchanged valid choice so the client can acknowledge it; no economy change, immediate DataStore call or promise of a completed cloud save. Writing attributes in order does not guarantee their network delivery order.

AudioPreferences applies a local selection immediately and coalesces pending values. Local Player attributes are RuleRoomEffectsVolume, RuleRoomMusicVolume, RuleRoomAudioMuted, RuleRoomUserReducedMotion and RuleRoomPreferenceStatus. Requests are serialized at least 0.6s apart, one in flight, bounded retries; acknowledgements require both a newer revision and the corresponding value. Late loading or older confirmation must not override a newer local selection. Session/fallback UI explicitly calls the preference temporary. Effective reduced motion is system preference OR user preference; stored false never disables system accessibility.

AudioController retains four cue voices and adds two independent music voices using the existing bundled Tone URI. An original eight-note, 24-second sparse laboratory phrase plays only in Waiting/Voting outside active participation. It stops for Rule/Break/InRound, mute, death/respawn and cleanup; cues briefly duck its independent mix. Effects and music volumes are separate. The lobby Audio button opens the scrollable settings panel; during an active trial, when the action button is visible, it remains a quick mute. Settings close on dangerous phases and conflicting menus; no full-screen touch blocker or PlayerModule modifications.

SpectatorPicker uses the existing SpectateNext button to open a bounded list of up to12 eligible living InRound players. Selecting a row chooses that participant; confirmed friends sort first only when opening, so late replies do not move a row beneath a press or change a selected camera. Friendship lookup is pcall-protected, two in flight and a bounded queue; stale callbacks after leave/rejoin/Destroy are ignored. The popup closes on B/Escape, hidden state, death/respawn, admission or phase change, releasing its selection/action binding. Native camera/touch/controller and actual friendship responses remain separate acceptance.

CONTENT01 is now integrated into the main GameConfig catalog and ordinary weighted deck: 12 catalog rules, still six trials per run. PressureWave is Spatial/Cosmic-weighted and ChangingWalls is Movement/Reflex-weighted; neither is the first beginner rule. Both use two 5s Warning / 7s Active / 1s Recovery beats, shifted opposite directions, a visible source strip inside the arena and 65 damage once per pass. Energy screens/walls never collide with characters. Server swept geometry checks body overlap and clips late samples to the deadline. They use ordinary roster survival, Flawless, awards and emergency Disabled_<RuleId> flags. The independent prototypes.project.json remains a historical research harness; production does not require it. Native QA01/UX04 remains unaccepted, not a reason to mislabel integrated code as a prototype.

## Integrated product package — 2026-11-08
