## Зависимости и границы

Roblox-рецепты используют существующие Studio/MCP и инструменты проекта. Навык не устанавливает движок, не меняет игровой контракт и не даёт разрешение на публикацию/платежи. Для Open Cloud нужны соответствующие права аккаунта.

Blender-навыки требуют Blender и выбранного MCP backend: upstream предпочитает официальный маршрут для Blender 5.1+, альтернативный ahujasid допускает 4.0+ с оговорками upstream. Упоминания `allowed-tools` — подсказки клиента, а не реальные выданные права или гарантия наличия API.

Скрипты обработки изображений импортируют `numpy`, `cv2` (opencv-python), `scipy`, `PIL` (Pillow), иногда `skimage` (scikit-image). `bpy` и `bmesh` относятся к Python внутри Blender. Проверка обнаружения навыка не проверяет эти окружения; результаты установки Blender/MCP учитываются отдельно. Скрипты, сетевые скачивания ассетов и Blender-рецепты здесь не запускались.

## Как выбирать навыки

Сначала `router` и инструкции проекта. Загружайте только подходящий навык, выбирая один из пересекающихся источников; не читайте все 82 тела одновременно. Префикс входит в имя явного вызова, например `$el4-roblox-networking`.

| Сценарий | Узкий вход | Что проверить после работы |
|---|---|---|
| Код Luau и модули | `$el4-roblox-luau` либо `$brain-roblox-luau-core` | Компиляция и соответствующие тесты проекта |
| Сохранения и защита remote | `$el4-roblox-data-stores`, `$brain-roblox-security` по необходимости | Отказ записи, повтор запроса, авторитет сервера |
| HUD и телефон | `$brain-roblox-gui` | Реальный viewport, safe areas и ввод |
| Моделирование ассета | `$ccb-text-to-blender` → `$ccb-blender-modeling` | Сцена, геометрия и визуальный результат |
| Референс/текстуры/экспорт | `$ccb-reference-to-3d`, `$ccb-blender-export` по задаче | Сопоставление с референсом и импорт в целевой движок |
| Проверка FPS и утечек | `$el4-roblox-performance` | Измерения реального процесса; не выводы по компиляции |

Эти сценарии задают точки входа. Автоматическая маршрутизация модели по всем запросам не тестировалась.

## Повторная проверка

Из корня репозитория (Python с PyYAML):

```powershell
python tools/skills/install_libraries.py --mode validate
python tools/skills/test_install_libraries.py -v
python tools/skills/verify_discovery.py
```

Для новой машины: `python tools/skills/install_libraries.py --mode install`. По умолчанию исходники помещаются в `build/skill-sources` внутри текущего репозитория; `build/` исключён из Git. Установщик отдельно получает точные закреплённые Git-объекты и проверяет HEAD, использует встроенный helper Codex и отказывается перезаписывать чужие файлы. Затем `--mode validate` использует тот же кэш. Другой путь задаётся `--sources-root`.

В первоначальной установке кэш уже находился вне репозитория. Для его повторной проверки в этой рабочей папке: `python tools/skills/install_libraries.py --mode validate --sources-root ../../work/env-skills/sources`. Это необязательный override, а не зависимость новой установки от структуры папок этой машины.

Регенерация каталога сохраняет прежнее доказательство обнаружения с исходной датой, если текущие имя, путь и описание совпадают. Она не выполняет новый запрос Codex. Запустите `verify_discovery.py`, когда требуется свежее подтверждение.
