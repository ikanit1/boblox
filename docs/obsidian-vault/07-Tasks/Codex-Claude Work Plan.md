# RuleRoom: план работ для Codex и Claude

> **Передача завершения пакета, 8 ноября 2026.** Разделение владения ниже сохранено как история задания. Его заменяет [CODEX_PLAN](../../CODEX_PLAN.md): Claude больше не редактирует checkout, интеграция и общая сборка переданы Codex. Итог — [SECOND_PACKAGE](../../SECOND_PACKAGE.md). Незакрытые критерии полного выпуска остаются в [[07-Tasks/Roadmap]], а не считаются выполненными передачей файлов.

Этот файл — рабочее задание для двух агентов, которые работают **одновременно в одном checkout**.
Порядок и критерии выпуска остаются в [[07-Tasks/Roadmap]] и [[10-Releases/Release Checklist]];
здесь — кто что делает и в каком порядке. Код и тесты остаются авторитетными.

> **Как читать.** Найди свою роль ниже («Ты — Codex» или «Ты — Claude»). Выполняй **только свои задачи**
> текущего этапа, по порядку. Чужие задачи читай, чтобы знать контракт, но не делай их.

## 0. Правила для обоих агентов

1. Прочитай `AGENTS.md` и `docs/ALPHA_CONTRACT.md` перед работой.
2. **Владение файлами строгое** (таблица в разделе 1). Чужой файл не редактируй даже «чуть-чуть».
   Нужна правка в чужом файле — опиши её в отчёте как запрос другому агенту.
3. В дереве есть чужие незакоммиченные правки. Не откатывай, не форматируй и не «чини» их.
4. Запрещено: `git commit/push/checkout/stash/reset`, публикация в Roblox, новые зависимости,
   замена системы профилей на ProfileStore. Коммитит пользователь.
5. `Build.ps1` и `tools/build_assets.py` запускает **только Claude** (генератор и сборка — общий ресурс).
   Codex запускает только свои тесты через `lune`, `stylua --check`, `selene` для своих файлов.
6. Инструменты: `~/.rokit/bin/{lune,rojo,stylua,selene}`. Если обёртки не запускаются —
   бинарники из `~/.rokit/tool-storage/...`. Если selene не может создать папку в AppData — напиши об этом.
7. Код: Luau `--!strict`, табы, комментарии в коде на английском, тексты игрока на русском.
   Цвет никогда не единственный сигнал: всегда символ + текст.
8. Каждое изменение поведения — с тестом, который **падает на старом коде** и проходит на новом.
   Проверь это (временно подставь версию из `git show HEAD:<file>` и верни свою).
9. Никогда не называй офлайн-тест «проверкой в Studio».
10. **Отчёт в конце задачи** (в ответе и, для Codex, в `-o` файле): что изменено по файлам, контракт
    (точные имена атрибутов/функций), вывод тестов, что не проверено, запросы другому агенту.

## 2. Общий контракт атрибутов

Сервер (Codex) выставляет, интерфейс (Claude) показывает. Интерфейс обязан работать, если атрибута ещё нет.

| Атрибут игрока | Тип | Смысл | Статус |
|---|---|---|---|
| `MovementWarning` | boolean | первое неправдоподобное движение в этапе: игрок возвращён, награда этапа снята | есть |
| `RunEnergy` | number | личные заряды ⚡ в финале текущего забега | есть |
| `BestRunScore` | number | лучший счёт за забег (профиль) | этап A |
| `BestRunSurvived` | number 0–6 | лучшее число успешных этапов (профиль) | этап A |
| `BestPracticeSeconds` | number или nil | лучшее время паркура (профиль) | этап A |
| `Flawless_<RuleId>` | number | прохождения правила без урона (профиль) | этап A |
| `NewRecord` | string | `""`, `"Score"`, `"Survived"`, `"Score,Survived"`; сброс в `BeginRun` | этап A |
| `TrialOutcome_N` | string | добавляется значение `"Forfeited"` (жив, награда снята) | этап A |

Правило финала (этап A): игрок с `Forfeited` в ReactorRush **считается живым для командного успеха
реактора**, но **не получает личную победу**.

## Этап A — закрыть текущий пакет (параллельно)

### Ты — Codex: A-C1, A-C2

**A-C1. Сохраняемые рекорды и мастерство.** Прогрессия сейчас заканчивается за 5–8 забегов.
1. Схема профиля v2 (`ProfileData`): `BestRunScore`, `BestRunSurvived`, `BestPracticeSeconds` (nil = нет),
   `Flawless` (RuleId → count, только id из `GameConfig.RuleOrder`). Миграции v0→v2 и v1→v2 без потерь,
   нормализация и ограничения как у существующих полей. Старый сервер (v1) не должен перезаписать v2
   (существующий `SchemaChanged`) — опиши поведение отката.
2. `ProfileService`:
   - `CompleteRun(player, won)` обновляет лучшие значения из `RunScore`/`RunSurvived` и выставляет `NewRecord`.
   - Новые методы `RecordPractice(player, seconds)` и `RecordFlawless(player, ruleId)`: валидация
     (конечное `seconds > 0`, `ruleId` из `RuleOrder`), та же проверка `readyScope`, что у наград.
   - `replicate` публикует атрибуты из раздела 2.
3. `PlayerRoster`: отслеживать урон участника в текущем этапе; выжил без урона и без `MovementWarning` →
   `profiles.RecordFlawless`. `NewRecord = ""` в `resetRunDisplay`. Расширь тип `Profiles`.
4. `Station.server`: валидный финиш паркура → `RecordPractice`. Доступ к сервису профилей — минимальный,
   без глобального состояния (обоснуй). Сессионный `PracticeBestSeconds` сохраняется, стартовое значение из профиля.

**A-C2. Исход `Forfeited` и правило финала.**
1. Игрок с `MovementWarning`, доживший до конца этапа, получает исход `"Forfeited"` (не `"Eliminated"`).
   `RunPresentation` и его тесты понимают этот исход (не успех и не поражение).
2. Правило финала из раздела 2. Минимально: `AwardSurvivors` сообщает число живых forfeited,
   `Main.server` учитывает их в `FinaleSuccess` (только эта строка).
3. Обнови разделы `ALPHA_CONTRACT.md` (Protocol, Roster APIs, Progression API).

**Тесты Codex этапа A:** миграции и мусор; рекорды переживают повторный вход; `NewRecord` только при
улучшении; неверные данные отвергаются; `Forfeited` в итогах; forfeited жив → реактор засчитан,
личной победы нет. Все существующие тесты своих модулей зелёные.

### Ты — Claude: A-L1 … A-L4

Сначала посмотри `git diff` по `src/client`, `AudioConfig`, `build_assets.py`, `assets`: часть работы
(предупреждение о движении, рекорды, звук, приглашение) могла уже быть начата. Готовое не переделывай — доведи и проверь.

**A-L1. Интерфейс.**
1. Во время Rule при `MovementWarning`: строка «Движение не подтверждено — награда этапа снята»
   в компактной панели, не перекрывая джойстик и прыжок.
2. Исход `Forfeited` в полоске этапов и итогах: свой символ + текст + цвет, смысл «жив, награда снята».
3. Итоги: «НОВЫЙ РЕКОРД: …» по `NewRecord`. `CollectionPanel`: блок «Рекорды и мастерство»
   (лучший счёт, лучший результат N/6, лучший паркур, безупречные прохождения по правилам), прокрутка на телефоне.
4. Все тексты — в `PlayerHints` с тестами в `PlayerHints.spec`.

**A-L2. Звук и приглашение** (если ещё не сделано).
1. Нарастающий сигнал в последнюю секунду `HazardStage=Warning`, сигнал «безопасно» при `Recovery`;
   mute и reduced motion; только встроенные `rbxasset://` звуки.
2. Кнопка «Позвать друзей» в лобби: `SocialService:CanSendGameInviteAsync` / `PromptGameInvite` в `pcall`,
   скрыта, если нельзя; добавить через генератор и перегенерировать.

**A-L3. Документация** (после завершения Codex): Roadmap, Dashboard, отчёт пакета по образцу
`docs/FIRST_SESSION.md`, Evidence Index — по всем изменениям: HUD TextBounds, SafeZone, поздний вход,
сохранения (shutdown/lease), категории колоды, лава, DisappearingTiles, RedLight/LowGravity/LaserSweep 40,
мягкая проверка движения, RunEnergy, рекорды, Forfeited. Явно: «проверено локально, в Studio не проверено».

**A-L4. Итоговая проверка этапа A** (последней, после Codex): проверить diff Codex построчно; затем
StyLua, Selene, все `tests/*.luau`, `rojo build`, `verify_world`, `verify_place`, `verify_model`,
`check_sources`. Отчёт пользователю: готово ли к коммиту.

**Точка синхронизации A:** пользователь коммитит после A-L4.

**B-L2. Правила в реальной физике** (с фикстурами B-C1): предупреждение до опасности, достижимость,

  правилам `ArenaRules`; доля выживания по правилам и длительность забега → `docs/qa/balance.json`.
  Критерий: бездействующий выбывает во всех 10 правилах; опытный проходит ≥ 90%.

### Ты — Claude
- **C-L1. Нарастание сложности** этапов 4–5 (короче предупреждение или плотнее волны) — только значениями
  в `GameConfig` по данным C-C2, с обоснованием в Rule Catalog.
- **C-L2. Видимые режимы голосования:** «Реакция»/«Космос» меняют цвет комнаты и показывают баннер режима
  во время забега.
