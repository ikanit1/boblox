# Rule Room

Read the installed game-development router once, then only the Roblox/domain skills needed.

## Source and ownership
Rojo files are authoritative. World and HUD XML are generated by tools/build_assets.py; modify the generator and regenerate. Never make durable changes only inside generated place files or a mapped Studio subtree.

Server owns rounds, health, scoring and hazard decisions. Clients display replicated state. See docs/ALPHA_CONTRACT.md before changing the protocol; CONTRACT.md describes the historical prototype only.

The user expanded scope to a complete playable alpha: six-trial runs, ten rules, voting, earnable cosmetics, quests and robust profile persistence. Canonical repository is https://github.com/ikanit1/boblox on main. Source pushes are authorized; game publication and paid products are separate. Prefer existing dependencies over new frameworks.

Assign each agent concrete files. Only one agent mutates a Studio instance at a time. Review sources, then run Build.ps1 and appropriate verification. Never call static compilation a Studio playtest. For networking/lifecycle work test at least two clients where possible.

## Commands
- powershell -ExecutionPolicy Bypass -File .\Build.ps1
- powershell -ExecutionPolicy Bypass -File .\Open-Studio.ps1
- powershell -ExecutionPolicy Bypass -File .\Serve.ps1

## Acceptance
One person can enter, complete or lose a round, see results, and begin the next round. Rules are announced before hazards. Every rule resets tiles, laser and gravity. Death and joining mid-round cannot grant rewards twice. HUD uses Russian text and readable symbols as well as colors. Test actual touch controls and observe server/client Output before device acceptance.
