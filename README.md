# Комната, которая меняет правила

Первый локальный прототип Roblox. Одна арена, автоматические раунды и три правила: нужный цвет, прыжок через лазер, низкая гравитация со звёздами. Можно играть одному. Интерфейс на русском. Очки и рекорд хранятся только до выхода с сервера.

## Запуск

1. Запустите **Start.cmd** в этой папке. Он проверит исходники, соберёт место и откроет его в Roblox Studio.
2. Войдите в Roblox Studio своим аккаунтом, если вход ещё не выполнен.
3. Нажмите **Play / F5**. Раунд начинается автоматически после подготовки персонажа. Управление: WASD и пробел; на телефоне — стандартные кнопки Roblox.

Это локальное место. Оно не опубликовано и не содержит платных продуктов.

## Подключение агента

Официальный плагин Roblox Studio для Codex установлен. MCP-сервер зарегистрирован под именем **Roblox_Studio**.

На этом компьютере зарегистрирован официальный `StudioMCP.exe` из установленной Studio 0.744. После обновления Studio используйте Quick Connect ниже, чтобы обновить путь регистрации, если прежняя версия будет удалена.

Когда место открыто, откройте **Assistant → … → Settings → MCP Servers** (в некоторых версиях **Manage MCP Servers**) и включите **Enable Studio as MCP server**. Если доступен **Quick Connect → ChatGPT (codex)**, включите его. Авторизацию и переключатель выполняет пользователь; пароль и коды агенту не нужны.

Если инструменты Studio ещё не появились в текущей беседе, после включения MCP откройте новую беседу Codex в этой папке и напишите: «Продолжи работу над RuleRoom, подключись к Studio и проверь прототип». Проверка соединения — `list_roblox_studios`, затем `get_studio_state`; одного наличия конфигурации недостаточно.

## Разработка

- `Build.ps1` — создать XML-ассеты, проверить Luau и собрать `build/RuleRoom.rbxlx`.
- `Serve.ps1` — Rojo на `127.0.0.1:34872`. В установленном плагине Rojo внутри Studio нажмите Connect и укажите этот порт.
- `src/server/` — серверные раунды, опасности, участники и очки.
- `src/shared/GameConfig.luau` — длительности и правила.
- `src/client/` — отображение серверного состояния.
- `tools/build_assets.py` — исходник арены и интерфейса; `assets/*.rbxmx` генерируются из него.
- `docs/CONTRACT.md` — протокол и границы работы агентов.
- `docs/toolchain.json` — версии инструментов, официальные источники, SHA256 и проверки установки.

Редактируйте исходники. Изменения только в собранном месте или в синхронизируемых объектах Studio будут потеряны при следующей сборке/синхронизации. Один агент управляет живой сценой; остальные работают в назначенных файлах.

## Проверка прототипа

Статические проверки и офлайн-проверки модели не запускают физику Roblox и не подтверждают удобство управления.

В Studio проверьте: полный раунд и повтор; исчезновение неправильных плиток после предупреждения; прыжок через луч; сбор звёзд; восстановление гравитации и пола; смерть/Reset; подключение во время раунда. Затем запустите Server & Clients с двумя клиентами и Device Emulator. В Output проверьте сервер и каждого клиента.

Критерий следующего шага: новый игрок понимает первое правило без объяснений и добровольно начинает ещё один раунд. Магазин, сохранения и расширение контента добавляются после такой проверки.
